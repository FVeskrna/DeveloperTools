## What it does

Paste YAML on one side and get equivalent, pretty-printed JSON on the other — or flip the direction for JSON to YAML. Errors are reported with the exact line number, so a bad indent in a 300-line Kubernetes manifest takes seconds to find instead of minutes.

## Examples

**Kubernetes manifest → JSON for an API call.** Deployment YAML converts directly to the JSON body that `kubectl` would send. Nested maps become objects, `env:` lists become arrays, and `value: 4500` stays a number.

**JSON API response → YAML for a config file.** Paste a response payload and flip the direction: you get clean, 2-space-indented YAML without quotes around keys — ready to drop into a Helm values file.

**Debugging a broken pipeline file.** A tab character or a mis-indented list item in `.gitlab-ci.yml` produces a parse error with the line number, typically something like `LINE 14: bad indentation of a mapping entry`.

## Edge cases & notes

- **Type coercion is the classic YAML trap**: unquoted `yes`, `on`, `3.10`, or `012345` may not survive as the strings you intended. The converter shows you exactly what a parser sees — which is often the fastest way to spot the problem.
- **Anchors and aliases** (`&base`, `*base`) are resolved and expanded in the JSON output; the deduplication is lost, but the data is equivalent.
- **Multi-document streams** (`---` separators) are not supported; convert one document at a time.
- JSON → YAML output uses a 100-character line width and block style for readability.
