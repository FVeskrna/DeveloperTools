## What it does

Compose Dataverse Web API `$filter` expressions from visual condition rows — field, operator, value, and value type — combined with `and`/`or`. The builder handles the quoting rules that cause most hand-written 400 errors: strings quoted with doubled apostrophes, GUIDs and numbers bare, functions like `contains()` wrapped correctly.

## Examples

**Active accounts containing "contoso".** The pre-filled rows produce:

```text
$filter=statecode eq 0 and contains(name,'contoso')
```

**Open opportunities above a threshold, by owner.** Rows: `statecode eq 0` (number), `estimatedvalue ge 50000` (number), `_ownerid_value eq 5f1c…` (guid) →

```text
$filter=statecode eq 0 and estimatedvalue ge 50000 and _ownerid_value eq 5f1c...
```

**Contacts with no email.** Operator `is null` needs no value: `emailaddress1 eq null`.

## Operator reference

| Operator | OData form | Example |
| --- | --- | --- |
| equals | `eq` | `statecode eq 0` |
| not equals | `ne` | `statuscode ne 2` |
| greater / less | `gt`, `ge`, `lt`, `le` | `revenue gt 100000` |
| contains | `contains(f,'v')` | `contains(name,'ltd')` |
| does not contain | `not contains(f,'v')` | `not contains(name,'test')` |
| starts / ends with | `startswith`, `endswith` | `startswith(name,'A')` |
| null check | `eq null` / `ne null` | `emailaddress1 ne null` |
| lookup equals | `_field_value eq guid` | `_ownerid_value eq a1b2…` |
| date on/after | `ge` with ISO date | `createdon ge 2026-01-01T00:00:00Z` |
| last N days | `Microsoft.Dynamics.CRM.LastXDays` | `Microsoft.Dynamics.CRM.LastXDays(PropertyName='createdon',PropertyValue=7)` |

## Edge cases & notes

- **Option set values are numbers** — `statuscode eq 1`, never `'1'`. Quoting them is the second most common 400 after quoted GUIDs.
- **Dates** compare as ISO 8601 UTC literals without quotes: `createdon ge 2026-07-01T00:00:00Z`. For date-only ("on this day") semantics prefer the CRM query functions, which respect the user's time zone.
- **Grouping**: the builder combines all rows with a single `and`/`or`. For mixed logic like `A and (B or C)`, generate the `or` group, then parenthesize and combine by hand — OData honors parentheses.
- **URL encoding**: when pasting into a raw HTTP request, encode spaces as `%20` (the example line under the output shows the encoded form). Client libraries and the browser's `fetch` handle this for you.
- Standard OData `$filter` works the same against any Web API endpoint — the conventions here (bare GUIDs, `_value` lookups) are the Dataverse-specific parts.
