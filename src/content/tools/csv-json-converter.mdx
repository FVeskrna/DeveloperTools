## What it does

Convert CSV exports into a JSON array of objects, or a JSON array back into CSV — with the delimiter auto-detected (comma, semicolon, or tab), a header-row toggle, and optional type inference. A preview table shows the first rows so you can verify columns landed correctly before copying the full output.

## Examples

**A semicolon-delimited Excel export.** The pre-filled sample uses semicolons, as European Excel does. Auto-detect reports `delimiter: semicolon`, and with type inference on, `revenue` comes out as a number and `active` as a boolean:

```json
{ "name": "Jana Novak", "city": "Brno", "revenue": 125000, "active": true }
```

**API response → spreadsheet.** Paste a JSON array of objects in JSON → CSV mode and open the result in Excel. Nested objects like `"address": {"city": "Brno"}` become an `address.city` column automatically.

**Headerless machine output.** Disable FIRST ROW IS HEADER for raw data without column names — rows become arrays in the JSON, or get generated `col1…colN` names in the preview.

## Edge cases & notes

- **Preserve-as-string cases:** zip codes (`01234`), phone numbers, and 18-digit ids all get damaged by type inference — that's what the toggle is for. When off, nothing is reinterpreted.
- **Ragged rows** (a line with fewer fields than the header) produce `null` values for the missing columns rather than failing the whole parse.
- **Column union on JSON → CSV:** if later objects have keys the first object lacks, the header is built from the union of all keys and missing cells are left empty — tools that read only the first object would silently drop those columns.
- **Round-tripping** CSV → JSON → CSV preserves data but normalizes formatting: quoting style and delimiter follow the output settings, not the original file.
- Very large files (tens of MB) are better handled by streaming tools; this page keeps everything in tab memory.
