## What it does

Paste two versions of a text and see exactly what changed: line-level differences with character-level highlighting inside changed lines, in either a unified (git-style) or side-by-side view. A stats line counts added, removed, and changed lines, and comparisons can ignore case or whitespace.

## Examples

**Two versions of a config file.** The pre-filled sample compares two releases of a service config: the version bump and port change are highlighted character-by-character (only `8080` → `8443` lights up, not the whole line), and the new `timeoutMs` line shows as a clean addition.

**"What did the ORM change in this SQL?"** Paste the query from yesterday's log and today's. Side-by-side view aligns the two statements so a changed `JOIN` condition or an extra predicate stands out immediately.

**Comparing API responses.** Two JSON payloads from staging and production — with IGNORE WHITESPACE enabled, formatting differences disappear and only real value changes remain.

## Edge cases & notes

- **Changed vs. added/removed:** when a block of removed lines is followed by a block of added lines, pairs are counted as *changed* and get inline highlighting; the surplus (if the blocks differ in length) counts as purely added or removed.
- **Whitespace-only differences** are the most common "why is this line marked?" surprise — trailing spaces and CRLF/LF both count as changes unless IGNORE WHITESPACE is on.
- **Very long lines** (over ~1,000 characters) skip character-level highlighting — a minified bundle diff at character granularity isn't readable anyway; the line-level diff still works.
- Order matters: the left/first pane is treated as the original, so swapped inputs invert every + and −.
