## What it does

Compose a Dataverse Web API `GET` query from form fields — entity set, `$select`, `$filter`, `$expand` with nested `$select`, `$orderby`, `$top`, `$count` — and watch the correctly encoded URL assemble live. Alongside it: the standard OData header preset with one-click copy, and a ready-to-paste `fetch()` or C# `HttpClient` snippet built around your exact query.

## Examples

**Active high-revenue accounts with their primary contact.** The pre-filled form produces:

```text
GET [org]/api/data/v9.2/accounts?$select=name,revenue,statecode
    &$filter=statecode eq 0 and revenue gt 100000
    &$expand=primarycontactid($select=fullname,emailaddress1)
    &$orderby=revenue desc&$top=10
```

(one line in reality — spaces inside the filter are `%20`-encoded for you).

**"Just give me a count."** Clear `$top`, enable `$count=true`, and the response's `@odata.count` tells you how many records match the filter without paging through them.

**From experiment to code.** Once the URL returns what you expect (paste it into a browser tab while logged in to your org — it works), flip the snippet toggle to C# and copy an `HttpClient` block with the headers already correct, including the annotation preference.

## Edge cases & notes

- **Entity set names are plural logical names** (`accounts`, `contacts`, `new_projectses` — yes, Dataverse pluralizes custom entities mechanically). A 404 with a valid-looking URL is almost always a singular/plural mistake.
- **Encoding:** spaces and quotes must be percent-encoded but `$`, `=`, `&`, commas, and parentheses must not be — over-encoding an OData query breaks it as reliably as under-encoding. The builder uses the encoding Dataverse actually accepts.
- **`$top` vs. paging:** `$top` caps the result set; for full extraction follow `@odata.nextLink` instead and set `Prefer: odata.maxpagesize`. Mixing `$top` with `$count=true` is allowed — the count ignores `$top`.
- **v9.2** is the stable version segment for current environments; older orgs may use v9.0/v9.1 — the path is the only thing you'd change.
- Authorization is a bearer token from Microsoft Entra ID; acquiring it (MSAL, connection strings, managed identity) is deliberately out of scope for the snippet's `accessToken` variable.
