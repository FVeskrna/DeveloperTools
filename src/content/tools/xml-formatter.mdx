## What it does

Paste XML to pretty-print it with your chosen indentation, minify it to a single line, or just check that it parses. Malformed input gets a precise error with the line number from the browser's native parser — the same parser your JavaScript would use.

## Examples

**An unreadable SOAP response.** One long line of `<soap:Envelope>…` becomes an indented tree where you can actually find the fault code. Namespaced tags are preserved exactly.

**Minifying a config for embedding.** Pretty XML minifies to a single line with inter-element whitespace stripped — handy for stuffing into a JSON string field or an environment variable.

**Finding the break.** Delete a closing tag from a 40-line document and the status flips to NOT WELL-FORMED with the offending line number, e.g. `LINE 23: Opening and ending tag mismatch`.

## Edge cases & notes

- **The XML declaration** (`<?xml version="1.0"?>`) is preserved from your input if present; the DOM parser itself discards it, so the tool re-attaches the original.
- **Attribute order** is kept as written. XML semantics say order doesn't matter, but diffs are cleaner when it's stable.
- **Entity references** like `&amp;` are decoded on parse and re-escaped on output — `&#38;` becomes `&amp;`, which is equivalent.
- Elements with no content are self-closed (`<spec />`), the conventional compact form.
