## What it does

Pretty-prints FetchXML with an attribute-alignment mode designed for how FetchXML is actually written: one attribute per line, lined up under the first, so `attribute`, `operator`, and `value` on your `<condition>` elements read like a table. One click copies the result as an escaped C# verbatim string for plugins and integration code.

## Examples

**A query from Advanced Find.** The pre-filled sample — accounts over 100k revenue with an outer join to the primary contact — arrives as one dense line. Formatted with alignment on, every `<condition>` and `<link-entity>` becomes individually readable, and the `alias` you need to reference in code (`pc.emailaddress1`) is easy to spot.

**Embedding in a plugin.** Press COPY AS C# STRING and paste:

```csharp
var fetchXml = @"
<fetch top=""50"">
  <entity name=""account"">
    ...
";
var results = service.RetrieveMultiple(new FetchExpression(fetchXml));
```

The doubled quotes are already handled — the classic copy-paste error (a stray unescaped `"` breaking the literal) can't happen.

**Reviewing a colleague's aggregation query.** Aligned attributes make it obvious when a `<condition>` uses `operator="on-or-after"` where the spec asked for `"on-or-before"` — the operators line up in a single column.

## Edge cases & notes

- **Line-number errors** come from the browser's native XML parser: an unclosed `<filter>` in a pasted query is reported with the exact line, which beats Dataverse's generic "Malformed FetchXML" server response.
- **`{0}` placeholders** used with `string.Format` survive untouched; remember that in a C# verbatim string `{` needs no escaping (that's interpolated strings, `$@"…"`).
- **Attribute order is preserved**, so `uitype`/`uiname` attributes some designers emit stay where they were.
- The escaped C# output targets classic verbatim strings; for C# 11+ you can also paste the plain formatted XML into a raw string literal (`"""…"""`) with no escaping at all.
