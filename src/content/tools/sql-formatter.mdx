## What it does

Turn a single-line query from a log or an ORM into readable, consistently indented SQL. Pick the dialect, indentation width, and keyword casing; the result updates as you type, entirely in-browser.

## Examples

**A logged query, unwrapped.** The pre-filled sample — a `SELECT` with two joins, `GROUP BY`, and `HAVING` crammed onto one line — becomes a query where each clause and join condition sits on its own line. Code review-ready.

**T-SQL from SQL Server Profiler.** Switch the dialect to T-SQL and square-bracket identifiers like `[dbo].[Orders]` and `TOP (20)` format correctly.

**BigQuery with backticks.** Dialect: BigQuery. Backtick-quoted project paths (`` `project.dataset.table` ``) and `STRUCT` types are understood and kept intact.

## Edge cases & notes

- **Dialect matters more than it looks**: PostgreSQL's `::` casts, MySQL's backticks, and T-SQL's `@variables` each tokenize differently. If output looks mangled, check the dialect first.
- **Comments are preserved** — both `-- line` and `/* block */` styles stay attached to the statement they precede.
- **`keywordCase: preserve`** leaves casing exactly as written, useful when your style guide is lowercase keywords.
- Extremely long `IN (…)` lists are wrapped; this is by design and does not affect execution.
